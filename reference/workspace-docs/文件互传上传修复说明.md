# 「文件互传」不能上传文件 —— 原因与修复

**结论先说**：文件管理器自带的 `libjsapi_fileserver.so` 里那个 HTTP 服务**只有 GET**，
内嵌页面就是一个只读的目录列表，插件里连 `upload` / `POST` / `multipart` 这些字眼都不存在
（只有一句 `get method failed %s`）。所以网页上既没有上传入口，也没有上传接口 —— 这不是
"哪里配错了"，而是**这个功能从来只实现了浏览/下载**。

修法：用同一套 jsapi ABI 重写一个 `fileServer` 插件（保留原有 API），加上流式上传。
已实机验证通过，并打进了 `miniapps/dist/file-manager-1.2.0-upload.amr`。

---

## 一、证据：原插件为什么不能上传

| 检查项 | 结果 |
|---|---|
| 原插件内嵌 HTML | 只有 `<h1>Index of …` + `Name/Size` 两列表格 + `HaaS FileServer` 页脚，**没有任何 `<form>` / `<input type=file>`** |
| 原插件字符串 | `upload` 0 处、`multipart` 0 处、`form-data` 0 处；只有 `get method failed %s` |
| 原插件导出 | `start` / `stop` / `getStatus` / `getPort`（`usage: start(port, rootPath)`） |
| 实测旧页面 | `GET /` → 200（目录列表）；`POST /upload` → **405 Method Not Allowed** |
| app 侧期望 | `$service_proxy.fileServer` + `getStatus().running` / `start(port, path)` / `stop()`，并订阅 `server_started` / `server_stopped` 事件 |

也就是说：**app 的 UI 叫「文件互传」，但它用的服务端只做了「传出去」这一半。**

## 二、修复方案

自己写一个 `fileServer` 插件（C + QuickJS C 模块），实现与原版一致的模块名/API，
并补上完整的双向传输：

```c
void custom_init_jsapis(void) { registerCModuleLoader("fileServer", loader); }
```

导出的模块对象（与原版一致，含 app 用到的具名导出）：

| 导出名 | 说明 |
|---|---|
| `default` / `FileServer` / `fileServer` | 三者指向同一个对象（app 用的是 `import { FileServer } from 'fileServer'`，少一个就 `SyntaxError: Could not find export 'FileServer'`） |

方法：

| 方法 | 说明 |
|---|---|
| `start(port, rootPath)` | 启动服务，返回状态对象 `{running, ok, code, port, root, ip, url, upload}` |
| `stop()` | 停止 |
| `getStatus()` | 同上状态对象（`running` 就是 app 用来判断"是否已启动"的字段） |
| `getPort()` / `isRunning()` / `getRoot()` | 补充查询 |
| `on(event, cb)` / `off(event)` | 订阅事件；`start` 成功时同步触发 `server_started`，`stop` 时触发 `server_stopped`，失败触发 `server_error` |

HTTP 接口：

| 请求 | 说明 |
|---|---|
| `GET /` | 新页面：**拖拽上传区 + 选择文件（多选）+ 新建文件夹 + 目录/文件列表** |
| `GET /?path=sub` | 浏览子目录 |
| `POST /upload?path=sub` | `multipart/form-data` 流式落盘，**不限大小**，支持多文件、中文名；重名自动加 `-1` |
| `GET /files/<rel>` | 下载，支持 `Range`（206），视频可拖动/断点续传 |
| `POST /mkdir?path=&name=` | 新建文件夹（已存在视为成功） |

安全性：路径过滤 `..`、文件名剥离目录部分、只绑定局域网。

## 三、开发中踩到并修掉的 5 个坑（都是真 bug）

1. **multipart 解析器死循环空转**：缓冲区塞满又找不到分隔符时 `recv` 不再推进 →
   该连接线程 100% 占 CPU，把笔拖到 ADB 掉线、表现为"笔变砖/offline"。
   → 重写为带压缩/扩容 + 任何情况下都保证前进（缓冲上限 16MB，超限直接报错）。
2. **文件尾部少 4019 字节**：`mp_find()` 找到分隔符就直接返回，**没把分隔符之前的数据写盘**。
   → 找到分隔符时先 flush 再返回（8MB 文件 md5 这才对得上）。
3. **插件里用 `popen()`**：多线程进程里 fork 有死锁风险，曾导致页面黑屏。
   → 换成 `getifaddrs()` 取本机 IP，不再起子进程。
4. **热替换正在被 mmap 的 `.so`**：框架进程里映射的还是旧文件，替换后点开 app 黑屏。
   → 替换插件后**必须重启词典笔**（`miniapp_cli install` 之前也同理）。
5. **少了具名导出**：只导出 `default` 时，框架日志里是
   `SyntaxError: Could not find export 'FileServer' in module 'fileServer'`，app 页面直接黑屏。
   → 补齐 `default` / `FileServer` / `fileServer` 三个导出。

## 四、安装方式

### A. 全新设备（推荐）：装打进包的 amr

```powershell
cd ydpen-adb
tools\adb.cmd push miniapps\dist\file-manager-1.2.0-upload.amr /userdisk/Favorite/miniapps/
tools\adb.cmd shell "miniapp_cli uninstall 8001771940015915"      # 装过就先卸载（覆盖安装不会重提取 libs）
tools\adb.cmd shell "miniapp_cli install /userdisk/Favorite/miniapps/file-manager-1.2.0-upload.amr"
```

> 注意：32 位 `arm` 目录里仍是原版插件（该包同时带 32 位库）。本机（RK3562/aarch64）走的是
> `arm64-cherry3566`，即自研版。32 位老机型装这个包不会获得上传能力。

### B. 已经装了文件管理器的机器：只换插件

```powershell
python tools\fileserver_plugin.py status            # 看当前是原版还是自研版
python tools\fileserver_plugin.py install           # 替换（自动把原版备份成 .orig）
# 然后重启词典笔（必须！让框架重新加载 .so）
python tools\fileserver_plugin.py restore           # 想还原原版时用，同样要重启
```

### C. 完全脱离 app 的独立文件服务器（调试/应急）

`tools\build\fssrv` 是同一个 HTTP 服务的独立可执行文件：

```powershell
tools\adb.cmd push tools\build\fssrv /tmp/fssrv
tools\adb.cmd shell "chmod +x /tmp/fssrv; nohup /tmp/fssrv 8080 /userdisk/Favorite >/tmp/fssrv.log 2>&1 &"
# 然后浏览器打开 http://<笔的IP>:8080/
```

## 五、怎么用

1. 笔上打开 **文件管理器 → 菜单 → 文件互传**（页面路由是 `fs`）。
2. 设置端口（默认 8080）和共享目录，点「启动服务」——现在界面会正确显示"已启动"，
   因为插件会发 `server_started` 事件，并且 `start()` 返回的状态对象里 `running` 为真。
3. 电脑浏览器打开 `http://<笔的IP>:8080/`：
   - **上传**：把文件拖进虚线框，或点「选择文件」（可多选；大文件有进度条）；
   - **下载**：点文件名（视频等支持拖动进度条）；
   - **新建文件夹**：右上按钮。
