## 日常怎么用

```powershell
cd C:\Users\Sever\Documents\deepseek-harness\default-workspace\ydpen-adb

# 1) 笔上：设置 → 法律监管 → 连点文本 10~15 下，直到提示“ADB 调试已打开”
# 2) 拔一下 USB 再插（这样 adbd 才会真正起来）
# 3) 看设备
tools\adb.cmd devices

# 4) 每次重启后 /tmp 会被清空，需要重新认证一次：
tools\adb.cmd shell auth         # 提示 password: 时输入 ydpen2026（不会回显）
#    看到 success. 后，本次开机内都不用再输密码了

# 5) 进去（root）
tools\adb.cmd shell
# 提示符会长这样：[root@YoudaoDictionaryPen-031:/]#
```

也可以走网络 adb（笔连上 WiFi 后，5555 端口是开着的）：

```powershell
tools\adb.cmd connect 192.168.1.xxx:5555
tools\adb.cmd -s 192.168.1.xxx:5555 shell
```

常用命令：

```powershell
tools\adb.cmd shell "uname -a; id; df -h"          # 看系统
tools\adb.cmd shell "ls -la /usr/bin | head"       # 看程序
tools\adb.cmd pull /usr/bin/adbd_auth.sh out\      # 取文件
tools\adb.cmd push 本地文件 /tmp/                  # 放进笔里
tools\adb.cmd shell "cat /proc/cpuinfo"            # CPU 信息
tools\adb.cmd reboot                               # 重启（认证后就能用了）
```

## 关键坑（都踩过了）

1. **`/tmp/.adb_auth_verified` 决定一切**：脚本第一行就是"这文件存在就放行"。
   每次重启后它没了，所以重启后要重新 `shell auth` 输一次密码。
2. **adbd 只在"拔线 → 重新开 ADB → 插线"这个顺序下才起来**：USB 接口一直在（Windows 里能看到
   `ADB Interface`），但 `adb devices` 会显示 `offline / no serial number` —— 那就是 adbd 没跑。
3. **连续 3 次密码错**，这一次的"ADB 窗口"就废了，得重新走第 2 步。
4. **升级响应的 `policy.install.rebootUpgrade` 必须是 `"true"`**：为 `false` 时词典笔把包下载完、
   界面停在"正在安装 100.00%"却不重启，更新永远不会真正应用。我们把它改成 `true` 后，
   笔下载完 2.1GB 后**自己重启**，然后就生效了。
5. **`/register/` 之类接口要透明转发给真服务器**：一开始我们把非 checkVersion 的请求回 404，
   词典笔的注册/上报会失败，容易把升级流程搞卡。
6. **adb 在 Windows 上写不了 `C:\Users\<你>\.android`**（DSH 沙箱拒绝），已用 junction 把
   `%USERPROFILE%\.android` 指向工作区里的 `.android`，所以 `tools\adb.cmd` 能正常生成 `adbkey`。
   别去删这个 junction，删了 adb 会报 `Permission denied`。
7. **官方 CDN 单连接极慢（0.5MB/s）还会掐断连接**，用 `tools\fast_download.py`（1MB 小块 + 32 并发）
   约 4.5MB/s，7 分钟下完 2.1GB。
8. **hosts 劫持用完记得撤**：`tools\hosts_tool.ps1 -Remove`。否则笔会一直看到"99.99.91 新版本"，
   反复下载 2.1GB。

## 想回滚？

- 固件回滚：用原厂备份 + RKDevTool（LOADER 模式）刷回，或者把我们改的哈希换回
  `302af1d80be1106586775350cc0a2c92`（等长替换，`patch_firmware.py patch --password` 做不到反向，
  但可以 `--old-hash 054bda46d56c8496e14e81d78f5a3c27` 配合手动哈希计算；最简单是直接刷备份镜像）。
- 只要在笔上（root）执行：
  ```sh
  sed -i 's/054bda46d56c8496e14e81d78f5a3c27/302af1d80be1106586775350cc0a2c92/' /usr/bin/adbd_auth.sh
  ```
  就把密码换回原厂哈希了（前提是 rootfs 可写；不可写则需重新刷机）。
